# Rules for the platform package

The platform package holds every program the deployment job runs: the read step, the filter of the vault's export, the reader of Wrangler's output that writes the deployment record, and the Pulumi program as a function with the driver that runs it through the Automation API. The root [AGENTS.md](../AGENTS.md) applies here too; these rules are the ones specific to this package.

- **A step program reads arguments and the platform's JSON files, writes JSON or shell exports built from literals, and evaluates nothing.** It is called by name from a few lines of shell in the pipeline file. A refusal names the key or the rule and exits non-zero, and the probe job matches refusals on their reason, so a message is part of the contract.

- **The package is in layers, and a dependency points inward.** The domain holds the platform's types and rules, the application its use cases and the ports they reach IO through, the adapters every file, process, network call and SDK, and each step program wires them for one command. A helper that knows nothing of the platform, such as a check on paths, goes in the lib, which every layer may import and which imports no layer. The domain and the application take data and return data: input read up front and output written at the end cross at the step program through an adapter, and only IO a use case decides mid-flow goes through a port. An adapter reaches the application only through a port. The lint configuration enforces the direction, so a new import that crosses it is a design change, never a rule to relax. A refusal is the domain's error, thrown from any layer and printed by the step program.

- **`nextnode.toml` has one definition: its schema.** The read step, the configuration check job and the type of the spec derive from it. A key, its type or a rule about its value goes into the schema, never into a check of its own; only a rule that depends on the checkout or the repository's name lives in the domain's environment module, which the read step calls with what CircleCI supplied. The list of environments is the schema's too, and the deployment job's parameter is checked against it by the read step.

- **Everything the program creates stays inside the program function.** The program runs inline in the driver's process, and Pulumi tracks resources only within the function it was given. A resource declared at module level, or in a callback that outlives the function, is lost or fails in ways the output does not explain.
- **An application resource is keyed by an entry of the spec, and its logical name never changes.** The spec is what the job read from `nextnode.toml`; it is the only input, and it never reaches the program as a file the project could rewrite. Pulumi identifies a resource by its logical name: renaming one makes Pulumi destroy the resource and create another, which for a domain or a database is an outage.
- **Keep shared approval resources platform-owned.** Their program reads platform configuration, never application files, and only the service workflow deploys them.
- **Return the identifiers the Worker needs, and nothing secret.** The driver prints the outputs as JSON and the job logs them, so an output is public by construction. A value the Worker must not know, or that must not appear in a log, stays a stack secret and is handed over another way.
- **The driver owns the backend and the passphrase.** The state bucket, its credentials derived from the platform token, the secrets provider and the stack selection are set in code, not in files a step would template. The pipeline installs the Pulumi CLI and the Cloudflare plugin at the versions this package's manifest pins for their SDKs, so bumping the SDKs here is the whole bump.
- **Write TypeScript that Node runs as is.** The job runs the driver with Node's type stripping, with no build step, so only erasable syntax is allowed: no enums, no parameter properties, no namespaces. The manifest's type check enforces it.
- **Check locally before a pull request, against the canary only.** Run the manifest's type check, then the driver in preview mode with a spec shaped like the job's and the platform project's secrets exported in the environment. The canary's stacks are free to use; a real project's stack is production state.
- **A new provider is a plugin the pipeline file installs.** The job installs plugins into the platform user's Pulumi home at the versions it reads from this package's manifest, without restoring executable content from another run. A provider whose SDK this manifest lists but whose plugin the pipeline file does not install is downloaded on every run, or not found when the network blocks it.
